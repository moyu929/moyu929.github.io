## 结论先说

**没有可以直接拿来用的。** 三条理由，任何一条都足以否掉：

1. **签名类项目的实际维护度远低于 star 数暗示的水平** —— 而且**全部没有许可证**
2. **中文家电参数数据集不存在** —— 搜到的全是能耗预测 ML 数据集，不是规格表
3. **签名逆向属灰区**，需要用户裁决（见下方「待裁决」）

通用抓取框架（Crawlab / scrapy-playwright）是干净的，但**解决不了本站的核心问题** ——
本站的瓶颈不是「没有爬虫框架」，是**京东/天猫/拼多多的商品页规格区本身就不服务端渲染**
（实测京东搜索跳 `risk_handler`、天猫/拼多多是空壳）。套框架进去仍然拿不到数据。

- 天猫/拼多多：HTTP 200 但返回空壳，纯客户端渲染

## 四、什么才真的有用

按投入产出排序：

1. **品牌官方商城的 XHR 接口**（美的正在进行，`scripts/midea-lookup.py`）——
   官方站点没有反爬障碍，数据结构化程度最高，且**合规无争议**
2. **苏宁易购**（已接入 `scripts/suning-lookup.py`）—— 纯 HTTP、无限流、合规
3. **中国家电网产品库** `detail.cheaa.com` —— 服务端渲染、带 `上市时间`，
   但**不能按型号搜**（搜索 API 索引的是新闻文章不是产品），只能爬品类列表。
   技术通路成立，**覆盖度需先小样本验证再投入**
4. 太平洋作为第二印证接入 —— 已在用

## 待裁决

**签名逆向算不算「绕过反爬」？**

`jd_h5st` 是京东 App 接口的请求签名。复现它能让自动化请求被站点当作合法客户端接受 ——
技术上是在绕过平台设置的技术性访问控制，但**没有绕过登录、没有绕过验证码，
拿的也是公开可见的商品参数**。

三条路，请选一条：

- **不采用**（当前默认）：保持「只走不绕过人机验证」的路线，只做品牌官方商城与
  服务端渲染的第三方。合规最稳，但京东/天猫这条路就此关闭。
- **采用但仅用于公开商品参数**：写进 SKILL.md 并限定用途，不碰任何需登录的数据。
  注意**许可证问题仍需单独解决**（这几个仓库都没有 LICENSE）。
- **先观望**：等许可证明确或上游有官方开放平台再议。
