# 美的官方商城接入 · 2026-10-05

**结论先行：能打通，但只对 95 款里的 15 款（16.1%）真正有用。**
接口是干净的纯 HTTP、无需签名、无验证码；但**官方商城只上架了 33% 的型号**，
且 `year`（上市时间）本接口根本给不了 —— 而这恰好是站内最大的空洞。

产出脚本：`scripts/midea-lookup.py`

---

## 0. 为什么不能照 `probe-specs.py` 的老办法判

美的在站内有 **95 款**（`data/*/products.json` 里 `brand == "美的"`，单一品牌最多）。
任务给的详情页基线：

```
$ python scripts/probe-specs.py --url "https://www.midea.cn/#/detail?skuId=15454"
✗ https://www.midea.cn/#/detail?skuId=15454 www.midea.cn  连通但不可用：只抽到 4 个规格字段
```

`data/_cache/probe-specs.json` 里那 4 个字段的样本是
`['家电产品', '首页', '自营', '¥999.00', '87天 08:35:58', '美的集团官方商城', '全国联保', '全场包邮']`
—— **全是导航栏与促销条噪声，没有一个是规格**。真实规格在浏览器里是有的，
只是 SPA 渲染前服务端拿不到。所以「不可用」的结论对，但原因不是没有规格表，
而是**判据要换成「背后的接口」**。

## 1. skuId → 型号/规格：接口找到了

`#/detail?skuId=` 里没有型号，`skuId` 是纯数字。把响应监听挂上去
（`page.on('response', ...)`），34 条响应里一眼看出两个业务接口：

| 用途 | 方法与 URL | `restParams` 关键键 |
|---|---|---|
| 详情（型号 + 规格表） | `POST https://www.midea.cn/api/cms_bff/mtc-bff-app/m2c/querySkuDetail` | `skuId` |
| 搜索（型号 → skuId） | `POST https://www.midea.cn/api/cms_bff/mtc-bff-app/m2c/productSearch` | `searchKeyword` |

（其余是 `getPcConfig` / `queryNavList` / `queryAddress` / `wx/*` / `iotsdk.midea.com` 埋点，
与规格无关。）

### 1.1 签名不需要 —— 六组对照实验

前端每次请求都在 `headParams` 里带一个 61 字符的 `sign`（形如
`e02ac436de344f729498263395de1dba17911850984890de1177c77524a7f965a36cf09d21345`，
含 `timestamp`，看起来像 HMAC）。**实测服务端不校验**：

| 请求体 | 结果 |
|---|---|
| 原样回放浏览器抓到的 payload | `code=000000` ✅ |
| 删掉 `sign` 字段 | `code=000000` ✅ |
| `sign` 改成 `"deadbeef"` | `code=000000` ✅ |
| 换当前时间戳 + 删掉 `sign` | `code=000000` ✅ |
| 整个 `headParams` 删掉 | `code=000000` ✅ |
| `{"restParams":{"skuId":"999999999"}}`（不存在） | `mtc-bff-app-COM-100601 查询商品不存在` ✅ |

所以 `querySkuDetail` 的**最小请求体**就是：

```bash
curl 'https://www.midea.cn/api/cms_bff/mtc-bff-app/m2c/querySkuDetail' \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://www.midea.cn' -H 'Referer: https://www.midea.cn/' \
  -d '{"restParams":{"skuId":"15454"}}'
```

`productSearch` 只有两个必填项：`sessionId`（任意 32 位 hex，`uuid4().hex` 即可）
与 `bizChannel`（固定 `"productSearch"`）。少了任一个会回
`mtc-bff-app-COM-999999 用户sessionId不能为空,业务渠道bizChannel不能为空`。

### 1.2 示例响应（`skuId=15454`，节选）

```jsonc
{"code":"000000","msg":"操作成功","data":{
  "itemId":"1000945",
  "mapSkuInfo":{"15454":{
    "skuId":"15454","itemCode":"21012400000933",
    "title":"【空调滤芯】COLMO滤网 FC-72CA2 睿极空调专属滤芯【适配机型：…】",
    "model":"FC-72CA2",              // ← 型号是独立字段
    "brandName":"COLMO","categoryName":"家用空调",
    "lv2CatName":"家电配件","lv3CatName":"空调滤芯等耗材",
    "salePrice":"9900","originPrice":"99900",   // 单位：分
    "attributeList":[                        // ← 规格表
      {"attrId":"102570","attrName":"适用品类","attrVal":"空调"}],
    "productPacking":{                      // ← 最稳的一块
      "indoorBodyLength":"240","indoorBodyWidth":"60","indoorBodyHeight":"240",
      "indoorPackingLength":"247","indoorPackingWidth":"65","indoorPackingHeight":"247",
      "grossWeight":"0.6","netWeight":"0.4"}}}}}
```

两个规格来源：

- **`attributeList`** —— 规格表。非空率**极不稳定**，实测跨 29 款从 `0/106` 到 `63/106`。
  空调 57 项、滚筒洗衣机 106 项、冰箱 56 项，内容是真的（`洗净比` / `循环风量` /
  `总容积（L）` / `噪音值[dB（A）]` / `能效等级` / `额定制冷功率（W）` / `APF` …）。
  **「有 attributeList」不等于「有规格」**，一半条目值是空的。
- **`productPacking`** —— 尺寸与重量，非空率显著更高，是本次最可靠的产出源。

## 2. 型号 → skuId：搜索接口是**模糊召回**，不是精确查

`productSearch` 可直接 curl（带 `sessionId`），但**排名极松**。实测反例：

| 站内 `model_code` | 搜索实际返回（节选） | 目标型号是否出现 |
|---|---|---|
| `MR-519WUSPZE`（冰箱） | 第 1 条即 `MR-519WUSPZE`（skuId 195371） | ✅ 命中 |
| `KJ800G-H Pro`（净化器） | `KJ1000G-T1000 Pro` / `KJ400G-RX400 Pro` / `KJ850G-RX800 Pro` | ❌ 前 20 无 |
| `MRO805-3000`（净水机） | `MRC828-3000` / `MRC806C-3000` / `MRC810-3000` | ❌ 前 20 无 |
| `MY-C5147`（电压力锅） | `MR-519WUSPZE` / `MR-457WUSPZE`（**冰箱**） | ❌ 前 20 无 |
| `KFR-72LW/MWD2`（空调） | `KFR-72LW/M20` / `N8YH2-1` / `N8HA1Ⅲ` / `PH2` | ❌ 前 20 无 |

所以**搜索结果里没有型号字段**，必须逐个 `querySkuDetail` 回查 `model` 才能核对。
候选深度从 8 提到 20，精确命中从 20/93 升到 31/93（+55%）—— 深度值得加。

站点地图 / 品类枚举页未发现可用入口（`queryNavList` 只给导航树，不给商品列表）。

## 3. ⚠️ 型号逐字相符仍会写错货 —— 美的特有坑

**这是本轮最重要的发现，苏宁脚本里没有对应防线。**
美的给配件**沿用主机型号**作为 `model` 字段，于是：

| 站内型号 | 搜到的 skuId | 该 skuId 实际是什么 |
|---|---|---|
| `MRO805-3000`（净水机） | 15561 | 「RO滤芯-5.5年 适用星河2.0净矿1200G…」**滤芯** |
| `G3E Pro`（微波炉） | 199950 | 「美的微波炉水箱组件/下单前先发型号给客服核对/适用于G3E Pro」**配件** |

两者的 `model` 字段都与站内 `model_code` **完全相符**。
更阴的是 **`lv3CatName` 救不了** —— 滤芯的 `lv3CatName` 写着「微波炉」、
水箱组件写着「微波炉」，因为**品类是继承自主机**的。

所以闸门必须落在**标题**上。词表还必须**窄**：
第一版把 `内胆` / `内锅` / `电池` / `排水` / `底座` 写进去，结果
「美的电热水瓶 5L容量 316母婴级不锈钢内胆 0塑」——一台**完整电热水瓶** ——
被误判成配件丢掉。最终只保留配件目录里几乎不会缺席的强信号
（`适用` / `专用` / `适配` / `滤芯` / `滤网` / `配件` / `耗材` / `组件` /
`零件` / `说明书` / `遥控器` / `排水管` / `阀门` / `电缆` / `电源线` / `胶泥` …）。

## 4. 尺寸轴序与包装尺寸（已用同型号钉死）

站内 `size` 口径是 **`宽×深×高`**（如空调 `840×311×200mm`）。
接口 `productPacking` 给的是 `indoorBodyLength / Width / Height`，**顺序不同但可映射**：

> `MF-KZC6521` 接口给 `390 / 276 / 345`，
> 而站内该型号**既有值正是 `390×276×345mm`** —— 逐位吻合。
> 故 `Length×Width×Height` ≡ 站内 `宽×深×高`。

同一次请求还给了 `indoorPacking{Length,Width,Height}`（`247/65/247`），那是**外箱**，
必须排除 —— 与 `suning-lookup.py` 排除「包装尺寸」是同一道闸。
重量只取 `netWeight`（净重），`grossWeight` 是毛重。
空调另有 `净重量(室外机)`，但接口**没有室内机净重**，故只写 `外41kg` 而不编室内值。

## 5. 采不到的字段（以及为什么不硬凑）

- **`year`（上市时间）—— 本接口给不了。**
  29 款命中项的 `attributeList` 里**没有任何**含「上市 / 发布 / 年」的字段。
  只有 `createTime`，但那是**上架时间**：实测 8 款互不相关的商品
  （空调 / 饮水机 / 电饭煲 / 管线机…）`createTime` **同为 `2024-07-24`**，是批量导入日。
  与 `suning-lookup.py` 丢弃日精度「上架日期」属同一类错误，**故不采**。
- **`month`、`miot_model`、`second_hand`、`pros` / `cons` 等** —— 接口无对应数据。
- **`official_price` —— 不采。** `salePrice` 是**促销后的实时成交价**，
  与站内「参考价」口径冲突（见 `字段覆盖率与降级清单_2026-10-04.md`）。
  只把 `originPrice`（页面上的**划线价**，页面注明「指商品专柜…」，
  且**单位是分**，如 `549900` → ¥5499）映射到 `ref_price`。
- **空调 `size_indoor`** —— `attributeList` 只有**室外机**尺寸，室内机尺寸接口没给
  （`41572` 连 `productPacking` 的机身尺寸都是空的）。

## 6. 限流与验证

- **未遇到任何人机验证 / 验证码。** 全程纯 `code=000000`。
- **无限流。** 93 次 `productSearch` + 1091 次 `querySkuDetail`
  （上限，`--cand 20`），5 线程并发 **77.9 秒**跑完，**零失败零限流**，
  折合约 15 req/s。全程累计约 2500 次请求（含前期探测），未触发任何拦截。
  不需要退避重试。
- ⚠️ **一个自造的假象限流值得记下来**：第一版脚本让所有线程共用同一个
  `--data-binary` 临时文件，并发下互相覆盖，报出随机的
  `业务渠道bizChannel不能为空,用户sessionId不能为空`，
  一度被误判成站点限流（7 次假失败，命中数被压到 20/93）。
  改成**每线程独立临时文件**后假失败归零、命中升到 31/93。
  **报「限流」之前先排除自己的竞态。**

## 8. 对全站的价值判断

**这不是一个能填 `year` / `official_price` 的来源**，而站内最大的两个空洞恰好就是这两个
（`suning-lookup.py` 的立项动机）。所以：

- **美的官方商城的定位应是「尺寸 / 重量补齐」**，不是「上市时间补齐」。
  15 款 × 24 字段，相对全站 1036 款的规模，**边际收益有限**。
- 真正值得带走的是**两个方法论**，可以复用到其他 SPA 商城：
  1. **`page.on('response')` 抓 XHR 是 hash 路由 SPA 的通用解法** ——
     比在渲染后的 DOM 里翻要快也准得多。
  2. **「型号逐字相符」这个闸门对配件型商城不够。** 凡是**配件复用主机型号**的商城
     （美的就是），必须再加一道**标题级**的耗材闸门，且 `lv3CatName` 不可信
     （耗材继承主机品类）。海尔/格力若有同类商城接入，建议先查这一条。
- 若后续要提覆盖率，**性价比更高的方向仍是 `year`**：美的这条线已确认走不通
  （`createTime` 是上架时间），应回到第三方（ZOL / 太平洋 / IT168）的
  `上市时间` 字段，或另找能给出真实上市日期的渠道。
