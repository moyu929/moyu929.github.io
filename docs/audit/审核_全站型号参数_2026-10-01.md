## 一、审核口径

1. 中国大陆官方商城、官网规格页、说明书 PDF 为第一来源。
2. 官方缺失时，使用 ZOL、太平洋电脑网、苏宁自营、京东自营等权威第三方；关键参数原则上要求两处独立来源印证。
3. 普通媒体、评测、自媒体和 AI 聚合内容只能用于印证，不能仅凭一条媒体给出参数定值。
4. `home.miot-spec.com` 只能交叉印证 MIoT 协议型号，不能代替零售型号代码、上市时间或官方参数。
5. 没有型号精确匹配的来源时，不能因为同系列或同容量看起来相近就判定参数属实。
6. 现有数据未改动；本报告只指出“已证据支持”“存疑”“明显错误/错挂”“缺失可查方向”。

## 二、项目结构与收录范围问题

### 1. 项目规则与当前数据范围冲突

现行 `skills/appliance-data-curation/SKILL.md` 仍写明只收录中国大陆的小米/米家自有品牌，但当前工作区已经导入约 **618 款竞品**，涉及美的、海尔、追觅、戴森、格力、松下、苏泊尔、九阳、石头、科沃斯、云鲸、添可、索尼、海信、TCL 等多个品牌。

这些竞品目前大量使用 `verify_status: 已核验（第三方）`，而该状态不在现行规范允许的三种枚举中。需要先由用户确定：

- **方案 A：继续做竞品横评。** 修改收录规则、schema 和状态枚举，明确竞品来源与官方价/参考价的字段边界；或
- **方案 B：维持“小米/米家全型号”定位。** 将竞品从主体产品统计中移出，另设竞品数据区，不与小米/米家产品混计。

在口径未统一前，不能把 1036 款全部称为“小米/米家产品”。

### 2. 型号代码缺失严重

939 款没有可用的 `model_code`。其中不少只有内部 `id`、产品系列名或 MIoT 协议型号。内部 id 和 MIoT 型号都不能替代零售型号代码，这会直接影响：

- 同名不同代是否去重；
- 不同容量/尺寸是否为独立型号；
- 大陆版、港版、海外版识别；
- 规格参数是否确实属于这一款产品。

### 3. 重复型号代码

检测到：

- `floor-washer/fw_5c`
- `floor-washer/fw_5pro_foam`

两条均使用 `model_code: F305`。需要核对是同一硬件不同套装、零售型号代码录错，还是应合并为一条。当前不能按两个独立型号统计。

### 4. 审核状态枚举不一致

现行规范允许：

- `已核验（多源）`
- `已核验（官方商城）`
- `待核验`

当前另有 618 款使用 `已核验（第三方）`。这不是当前规范的合法状态，必须在整改前统一处理；不能仅通过改文字绕过来源核验。

## 三、已有报告能够确认的问题

### 1. 官方链接错挂

已有报告 `docs/audit/审计_空气净化至洗碗机.md` 明确记录了多起错挂：

- 空气净化器链接落到冰箱、电饭煲页面；
- 加湿器链接落到手机、键鼠、其他空气净化器页面；
- 风扇链接落到汽车模型、标签纸、保温杯、耳机、智能屏；
- 除湿机链接落到鸳鸯锅、扫地机器人；
- 冰箱链接落到其他冰箱/风扇/香氛机；
- 洗碗机链接落到充电宝、饭煲、卫衣、打印机；
- 微波炉链接落到手机；
- 电压力锅链接落到 Redmi 电视。

这些 URL 不能继续作为对应 SKU 的参数依据，应逐条清理或改为“查不到”。

### 2. 米家 IH 电饭煲 4L 型号冲突

历史报告指出 `rice-cooker/rc_ih_4l` 当前写为 `IHFB01CM`，而大陆 4L 官方规格页对应 `IHFB02CM`；`IHFB01CM` 可能是 3L 版本。应先确认该条产品容量和型号是否错配，再决定改型号或改容量。

参考：

- [米家 IH 电饭煲参数页](https://www.mi.com/dianfanbao2/specs)
- [米家 IH 电饭煲 4L 参数页](https://www.mi.com/dianfanbao2-4l/specs)

### 3. 米家空气净化器 MAX 的 CADR 口径问题

历史报告指出官方规格区分了颗粒物 CADR “大于 800m³/h”和实测 1000m³/h，而当前字段只写 `800`。这会混淆额定宣传口径与实测口径。建议拆分额定/实测字段，或至少保留大于号并在来源说明中注明口径。

参考：[米家空气净化器 MAX 参数页](https://www.mi.com/airmax/specs)

### 4. 竞品导入值需要另行审计

竞品字段中出现第三方参数值、参考价、HTML 实体和未统一单位。例如空气净化器竞品数据中出现 `m&#179`，说明部分抓取结果尚未清洗。浴霸、洗地机、吸尘器等品类还存在功率、容量、真空度单位错标风险。按照项目规则，这类可疑值应宁缺勿错，保留“查不到”并记录原因。

## 五、缺失参数能否调查到

| 参数类型 | 可调查性 | 首选来源 | 判断 |
| --- | --- | --- | --- |
| 零售型号代码 | 多数可查；停产老款不一定 | 官方规格页、说明书 PDF、铭牌、能效备案 | P0，优先补；不能用 MIoT 代替 |
| 容量、额定功率、尺寸、重量 | 多数可查 | 说明书/规格页/铭牌 | 对型号精确匹配后通常可补 |
| 官方在售价 | 在售款可查；历史价会变 | 官方商城，记录核查日期 | 可补，但不能当长期固定值 |
| 核心性能指标 | 多数可查，但口径可能不同 | 官方规格页；缺失时两家独立权威第三方 | 额定/实测分开；冲突留空 |
| 上市年份和月份 | 在售款部分可查，停产款不稳定 | 官方发布新闻、首发公告、备案 | 不得使用 MIoT `verified_time` 代替 |
| 滤芯/耗材成本 | 部分可查 | 官方耗材页和官方商城 | 需注明核查日期和规格 |
| 二手价、优缺点 | 不属于稳定官方技术参数 | 电商历史价、评测 | 单独标参考/编辑内容，不用于“已核验参数” |
| 安全、电气、健康相关字段 | 必须谨慎 | 官方说明书、认证/备案 | 不可仅凭媒体或相似型号补值 |

### 参数补全优先级

1. **P0：型号身份**：先补零售型号代码、品牌、系列、容量/尺寸版本和大陆销售证据。
2. **P1：核心参数**：按品类补额定功率、容量、尺寸、重量、关键性能；每项登记来源。
3. **P2：编辑性字段**：补价格、上市年月、耗材成本、优缺点和图片。
4. **不建议强行补全**：二手价、长期稳定的官方价、主观优缺点、无法区分额定/实测的数据。

## 六、建议整改顺序

### P0：先处理口径与结构

- 明确是否正式保留 618 款竞品。
- 将 `已核验（第三方）` 纳入正式规范，或将这批竞品移出主体数据。
- 修复/清理所有错挂 `verify_url`。
- 处理 `floor-washer` 重复 `F305`。
- 把没有可追溯来源但目前标为“已核验”的记录降级为 `待核验`，不要只改状态不补来源。

### P1：逐批核验小米/米家主体型号

建议按以下顺序分批，每批约 20—50 款：

1. 空气净化器、空调、洗衣机、冰箱、净水器、智能门锁、电视、投影仪；
2. 扫地机器人、无线吸尘器、洗地机、风扇、加湿器、除湿机、热水器、浴霸；
3. 厨房小家电与个护产品；
4. 竞品单独处理，不与主体混审。

每一批必须先拍产品级审核快照；整改方在快照 release 前不得改产品字段。

### P2：逐字段补充与报告闭环

每个确认值都应同步：

- 更新 `verify_status`、`verify_date`、`verify_source`、`verify_url`、`change_log`、`updated_at`；
- 将来源登记到 `data/_sources/provenance.json` 或对应 `patches/*.json`；
- 通过 `npm run validate` 和 `npm run audit:check`；
- 提交信息引用本报告文件名。
