# 审核报告归档

本目录存放各轮**产品数据审核报告**（由审核 Agent 产出），命名 `审核_<范围>_<YYYY-MM-DD>.md`。
报告模板见仓库根目录 [AGENTS.md](../../AGENTS.md) 第 8 节。

## 用法

- **日常审核不再需要快照锁**（2026-10-02 起）：产品级互斥由「分区流转协议」天然保证
  （`flow:recall` 把产品移出已入库区即是物理冻结），审核时**快照 id 留空即可**。
- 快照锁已降级为**结构冻结工具**，只在两类场景使用：schema 大改 / 字段批量迁移 / 脚本全量重写数据，
  以及**发版验收**前把全站拍成快照冻结。此时报告才需要写明快照 id（对应 `data/_locks/` 里的文件），
  并由审核方 `npm run audit:release -- <快照id>` 解除。
  ⚠️ 结构冻结生效期间**暂停所有 flow 流转**（召回/入库会搬动库内产品，`audit:check` 会把正常动作报成越界）。
- 按报告整改时在 commit 信息里引用报告文件名，并同步更新产品的 6 个审核标注字段。
  涉及分区流转的动作，提交信息请带 `flow` 标记（见 `AGENTS.md` 第 5 节）。

## ⚠️ 关于历史报告中的口径

早期报告（如 `审计_空气净化至洗碗机.md`）采用过**更严格**的规则，例如「严禁用媒体参数补齐」。
该口径已被放宽，**现行规则以 [`skills/appliance-data-curation/SKILL.md`](../../skills/appliance-data-curation/SKILL.md) 为准**：

> 媒体参数**可以作为参考，用于印证**已知信息；但**不能仅凭媒体这一单一来源**给产品定下参数值。

历史报告保留原样不改（它们是当时的审核依据记录），阅读时请注意口径差异。
